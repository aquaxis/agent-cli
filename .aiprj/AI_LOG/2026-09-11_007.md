## 2. What was built

| Area | Change |
|---|---|
| `src/ipc/mod.rs`, `src/ipc/server.rs` | `IpcMessage::Context { from, from_name, text }` — the same field names `Prompt` uses — and its `Ack` in the server's response table. The seven existing variants are untouched. |
| `src/app.rs` | One reader arm in **both** IPC loops mapping it to `AgentInput::Context` with `ContextSource::Peer`; a headless child can therefore receive reports from its own children. |
| `src/agent.rs` | `ContextSource::Peer { from, from_name }`, the pure `peer_context_text` giving the appended text the `[peer report from <name> (<id>)]` header a peer prompt already carries, and a handler that branches on the source: `Shell` unchanged and silent, `Peer` logged and announced with **one** `AgentEvent::Info`. No `TurnStart`, no `Done`, no provider call. |
| `src/log.rs` | `LogEvent::PeerContext { from, text }`. |
| `src/tools/send_to.rs` | `delivery` (`"prompt"` \| `"report"` \| `"ask"`) resolved ahead of the deprecated `wait_reply` alias; an unknown value refused with the three named; each result says which delivery was used; and the old-peer fallback — an `Error` reply triggers a resend as a prompt with the reason reported. |
| Docs | `doc/tools.md` (`send_to` rewritten around `delivery`, plus the fan-out pattern), `doc/usage.md`, `doc/architecture.md`, `doc/troubleshooting.md`, `README.md`, `README_ja.md`, `CHANGELOG.md`. |

## 4. Verification

- `cargo build` clean. `cargo test`: **480 unit + 4 integration, 0 failed**
  (476 at the v0.16.0 baseline) — 7 new tests.
- `clippy --all-targets`: the v0.16.0 warning set exactly.
- **The pattern, with a live provider** — the point of the cycle: the agent
  spawned two children with report-back instructions in their initial prompts,
  **four reports arrived**, each shown as one
  `[info] peer report from agent-…: N characters added to the conversation`,
  and **zero turns ran between the first and the last report**. Asked afterwards
  to combine them, it answered from both topics. Before this cycle each of those
  four would have cost a provider call and produced an answer with no recipient.
- **Mixed versions**: a **v0.16.0** binary built from the release tag answers a
  `context` message with
  `parse error: unknown variant \`context\`, expected one of \`prompt\` …`,
  keeps the connection, and accepts an ordinary prompt immediately afterwards —
  the two facts the fallback rests on, confirmed rather than assumed (C-05).
- **Wire compatibility** is pinned by a test: all seven pre-existing messages are
  compared against fixed byte samples, so a reshape fails the build rather than a
  peer.
- **End to end**: an integration test sends a `context` message to a real agent's
  socket and asserts its conversation log holds the text under `peer_context`
  with **no** assistant turn, leaving no process behind.
- **Non-regression**: `spawn` / `list` / `list --group` / `groups` / `stop`
  output is identical to v0.16.0 (ids, pids and timestamps normalised).
