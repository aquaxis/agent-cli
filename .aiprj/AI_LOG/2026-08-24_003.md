## Summary

At the user's request, the three items deferred in log `_002` (AS-02, AS-04,
AS-05) were implemented as a follow-up to the detached-spawn feature.

- **AS-05 / FR-18** — `src/cli.rs` `RunArgs::provider` help now lists all seven
  kinds including `claude-code`.
- **AS-04 / FR-17** — `commands::spawn_detached` hardened with a **double fork**:
  the intermediate `setsid`s and `_exit`s, the launcher `child.wait()`s to reap
  it, and the grandchild (`serve`) is reparented to init — no zombie under a
  long-lived launcher, and full terminal detachment. Its signature is now
  `(config_path, registry_dir, args)`; registration matches a **new registry id**
  (+ `--name`), not pid (the grandchild's pid differs from the launched pid).
- **AS-02 / FR-16** — LLM-callable `spawn` tool (`src/tools/spawn.rs`), **opt-in**
  (registered as a candidate but not in the default `[tools] enabled`). It takes
  optional name/provider/model/persona/prompt, calls `spawn_detached`, and can
  deliver a fire-and-forget initial prompt. `Agent` and `ToolCtx` gained a
  `ConfigSource` field so the tool can reach the config path; `ConfigSource` now
  derives `Default`.

## Design notes / decisions

- The `spawn` tool is **opt-in** by deliberate choice: autonomous process
  creation is higher-impact than peer messaging (`send_to`, which is default-on).
  The `spawn` subcommand and `/spawn` REPL command remain always available.
- Double fork required moving registration from pid-match to new-id-match; the
  `serve` process still registers its own real pid, so `stop`'s SIGTERM fallback
  and the integration test's `/proc/<pid>` liveness check remain correct.
- Headless `serve` still forces tool auto-approve (no console for y/N); a
  spawned agent therefore auto-approves its own tools. Left as designed;
  flagged to the user as a confirmable behaviour, not changed.
