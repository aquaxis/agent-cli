## Summary

Implemented `agent-cli update`, a self-update subcommand, per
`AI_PRJ_REQUIREMENTS.md` / `AI_PRJ_DESIGN.md` / `AI_PRJ_TASKS.md`
(FR-01 – FR-11). Because agent-cli publishes no prebuilt binaries — installation
is a source build (`install.sh` → `cargo install`) — the update mirrors that
model: it looks up the latest GitHub release, and if newer rebuilds from the tag
into the running binary's install prefix, then verifies.

- **`src/update.rs`** (new module): a pure core (semver parse/compare,
  `owner/repo` from `CARGO_PKG_REPOSITORY`, tag extraction from the release/tags
  JSON, install-prefix derivation from `current_exe()`) wrapped by three I/O
  edges — a `reqwest` GET to `releases/latest` (→ `404` fallback to `tags`), a
  `cargo install --git <repo> (--tag|--branch) <ref> agent-cli --root <prefix>
  --force` (with a no-`--locked` retry), and a `--version` verify.
- **Flags**: `--check` (report only, no changes, exit 0), `--force` (reinstall /
  allow same-or-older `--ref`), `--yes` (skip confirmation; non-TTY refuses
  without it), `--ref <tag|branch>` (target a specific ref).
- **Safety**: confirmation before replacing the binary (TTY prompt showing
  from→to + prefix); `cargo install`'s temp-build-then-move gives an atomic
  self-replace; success only after the new binary answers `--version`; missing
  `cargo` → rustup guidance; network errors are clear, never a panic.
- **No new dependency** — reuses `reqwest`, `serde_json`, `std`/`tokio` process,
  and a hand-rolled semver.

### Refinement over the spec (recorded for consistency)

The design had `run` always fetch the latest tag first. During the `--check`
smoke I confirmed the repo currently has **no releases and no git tags**
(`releases/latest` → 404, `tags` → `[]`). Two adjustments:

1. The latest-tag lookup is **best-effort when an explicit `--ref` is given**
   (only `--check` and the default path hard-require it), so `update --ref main`
   works before any release is tagged.
2. The no-release error carries an actionable `--ref <branch|tag>` hint.

Neither contradicts FR-05/AS-05; both are documented in the tasks and troublesho
oting doc.

## Note for maintainers

`agent-cli update` (default, no `--ref`) needs a published GitHub **release** or
`vX.Y.Z` **tag** to target. The repository currently has none (the "Release
vX.Y.Z" commits are not tagged), so until a tag/release exists, upgrades must use
`agent-cli update --ref main` (or an explicit ref).
