## Follow-up exchanges

Two requests arrived after the merge, both asking for `git commit` / `git push`
/ `gh pr create` / `gh pr merge`, the second prefixed with マイナーバージョン
アップ.

**Nothing was executed for either.** The state was checked first, and all four
were already done: the tree was clean on `main`, local and remote `main` were
the same commit, and PR #21 was merged.

The second request was ambiguous in a way that mattered — it could mean "you
missed the version bump" or "bump again to 0.21.0". Since `[Unreleased]` was
empty and there were no changes since v0.20.0, the second reading would have
published a release tag with nothing in it. That was put to the user rather than
guessed at, and the answer was to do nothing.

Worth recording as a habit for the next cycle: a repeated command sequence is
not automatically a request to repeat the work. Checking the state before acting
cost one command and avoided an empty release.

## What the next cycle should know

- **The permission rules are a guardrail, not a sandbox**, and `doc/config.md`
  §12.6 says so with the four commands that get around `bash(rm:*)` spelled out.
  That honesty is load-bearing — a reader who believes otherwise is worse off
  than one with no rules at all. Do not let a later change quietly overstate it.
- **A new tool needs an entry in `permissions::subject_of`**, or an explicit
  record that it has none. `CONTRIBUTING.md`'s checklist now says so. A tool
  missing from that table can only ever be named by a bare `tool` rule.
- **Two behaviour changes shipped here** and will generate questions: anyone
  with both `config.toml` files will start seeing user-level keys the project
  file does not override, and `/auto on` no longer lets a denied call through.
  `agent-cli doctor` prints the whole config chain, which is the diagnosis path
  for the first; `/permissions` names the rule, which is the path for the second.
- **`.aiprj/` is gitignored**, so the three documents and these logs live on disk
  only and are not part of any commit. That is the existing arrangement, not an
  oversight.
- **`.aiprj/instructions.md` still carries this cycle's instruction.** A new
  instruction there starts the next cycle, at which point the three documents are
  rewritten for it.
