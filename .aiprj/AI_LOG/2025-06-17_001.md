### Cursor Position Fix (User-reported bug)
- **Problem**: `InputState.cursor` is a byte offset, but `redraw_prompt`/`redraw_approval_prompt` used `prompt.len() + state.cursor` directly as the terminal column position. For multi-byte characters (CJK, emoji, etc.), byte offset ≠ display column, causing the cursor to appear at the wrong position.
- **Fix**:
  1. Added `unicode-width` crate dependency to `Cargo.toml`.
  2. Added `display_cursor()` and `display_width()` methods to `InputState` in `src/editor.rs`. `display_cursor()` computes the display column width of the text before the byte offset. `display_width()` computes the total display width of the line.
  3. Modified `redraw_prompt` and `redraw_approval_prompt` in `src/app.rs` to use `state.display_cursor()` instead of `state.cursor` for the `MoveToColumn` call.
- **New tests in `src/editor.rs`**:
  - `display_width_ascii`
  - `display_width_cjk`
  - `display_cursor_ascii`
  - `display_cursor_midline_ascii`
  - `display_cursor_cjk_at_beginning`
  - `display_cursor_cjk_at_end`
  - `display_cursor_multiple_cjk`
  - `display_cursor_cjk_fullwidth`
