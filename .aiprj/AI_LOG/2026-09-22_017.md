## The two errors found in the documented matrix (BL-07)

The delivery matrix was re-measured with three independent harnesses (fresh
tmux server per cell, payloads tagged per cell, delivery judged on the outer
pty; tmux 3.6, `xterm-256color`), and confirmed against tmux 3.6's own source.

1. **`set-clipboard external` does not forward a program-emitted bare form.**
   tmux 3.6's `input_osc_52` reads `state = options_get_number(global_options,
   "set-clipboard"); if (state != 2) return;` — only `on` (2) processes the
   sequence at all. Measured: bare delivered with `on`; dropped with
   `external` (the default) and `off`. The documents' "tmux's default is
   `external`, which also forwards" was wrong.
2. **The `Ms` check reads a false negative.** Plain `infocmp "$TERM" | grep
   Ms` omits extended capabilities and reported no `Ms` on this system — the
   matrix had marked every bare-form cell "not delivered (absent here)". Two
   independent facts overturn that: `infocmp -x "$TERM"` shows
   `Ms=\E]52;%p1%s;%p2%s\007` present, and the tmux server's verbose log logs
   `IDENTIFY_TERMINFO Ms=\033]52;%p1%s;%p2%s\a` — tmux's own terminfo view
   carries it. Measured again with `sc=on`: delivered.

Corrected matrix (tmux 3.6, outer `xterm-256color`):

| `allow-passthrough` (pane, default off) | `set-clipboard` (global, default `external`) | bare form | wrapped form |
|---|---|---|---|
| off | off or `external` | consumed | dropped |
| off | on | **forwarded** when tmux sees `Ms` for the outer terminal | dropped |
| on | off or `external` | consumed | **forwarded** |
| on | on | **forwarded** (same `Ms` note) | **forwarded** |

Under the stock defaults **neither** form is delivered — the cycle's central
defect claim and its fix stand unchanged; only the two supporting statements
were wrong.

Also measured and discarded as an artifact: mid-session
`set-option -as terminal-overrides` does not change what a running server
already built for the outer terminal (cells stayed identical with `Ms` forced
present and cleared), and a `Ms` override written into a tmux `.conf` file
lost its ESC byte on the way in (`yylex_token: xterm-256color:Ms=E]52`) — so
the forced-`Ms` cells are judged from the server log plus the system `infocmp
-x` rather than from those cells alone.
