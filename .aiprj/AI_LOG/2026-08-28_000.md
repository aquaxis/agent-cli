## Summary

Implemented **MCP (Model Context Protocol) client** support per
`AI_PRJ_REQUIREMENTS.md` / `AI_PRJ_DESIGN.md` / `AI_PRJ_TASKS.md`
(FR-01 – FR-12). agent-cli now connects to external MCP servers declared in a
new `[[mcp.servers]]` config section, launches each over **stdio**, performs the
JSON-RPC 2.0 handshake (`initialize` → `notifications/initialized` →
`tools/list`), and registers every discovered tool under the namespaced key
`mcp__<server>__<tool>` so the agent can call it through the normal loop and
approval gate. Invoking such a tool forwards to the server's `tools/call`.

- **`src/mcp/proto.rs`** (new, pure): tool-name mangling + sanitization, JSON-RPC
  request/notification construction, reply parsing (`result` vs `error`),
  `tools/list` extraction, and `tools/call` content flattening (`isError` →
  error). 5 unit tests.
- **`src/mcp/client.rs`** (new, I/O): `McpClient` spawns the server (stdin/stdout
  piped, stderr null), runs a background reader task that routes replies by `id`
  to `oneshot`s, exposes `call`/`notify`, bounds the handshake and every call by
  `init_timeout_ms`, and on `Drop` aborts the reader and kills the child.
- **`src/mcp/mod.rs`** (new): `McpTool` (`Arc<dyn Tool>` holding an
  `Arc<McpClient>`); `connect_all` (fail-soft per server); `probe_all` for the
  diagnostics; `ServerProbe`.
- **`src/tools/mod.rs`**: `Tool::name`/`description` changed from `&'static str`
  to `&str` (mechanical; the 11 built-ins are unchanged in behaviour); new
  `ToolRegistry::attach` inserts MCP tools honoring the persona allow/deny lists.
- **`src/config.rs`**: `McpConfig` + `McpServerConfig` (`name`, `command`,
  `args`, `env`, `cwd`, `enabled`, `transport`) + `[mcp] init_timeout_ms`;
  commented example in `DEFAULT_CONFIG`.
- **`src/cli.rs` / `src/main.rs` / `src/commands.rs`**: `agent-cli mcp list`
  subcommand and an MCP section in `agent-cli doctor` (both via `probe_all`).
- **`src/error.rs`**: `AppError::Mcp(String)` + `AppError::mcp()`.
- **`src/app.rs`**: async `connect_all` + `attach` wired after the synchronous
  `ToolRegistry::build` in `run` and `run_headless`.

**Scope honoured:** MCP *client* only (the instruction says "access to MCP
servers"); **stdio** transport only; MCP **tools** only. No new crate dependency
(JSON-RPC over `tokio::process` + `serde_json`). Additive: with no
`[[mcp.servers]]`, behaviour is unchanged.

## Deviations from the draft design (docs reconciled)

- **`selftest` not wired.** The draft listed `commands::selftest` as a third
  wiring site; its registry is built only to exercise `bash`, so connecting MCP
  servers there would spawn subprocesses for no benefit. Wired into `run` /
  `run_headless` only. Design §8 and requirements AC-03 updated.
- **Registration is a method.** `ToolRegistry::attach(extra, allowed, denied)`
  rather than a free `attach_mcp` fn, so the two call sites share one
  implementation. Design §8 / task T-04 updated.
