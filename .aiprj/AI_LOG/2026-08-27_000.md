## Summary

Implemented a **group identifier** for agent-cli and a **group detection**
command, per `AI_PRJ_REQUIREMENTS.md` / `AI_PRJ_DESIGN.md` / `AI_PRJ_TASKS.md`
(FR-01 – FR-16). A group is an optional label threaded through the existing
identity → registry → discovery path:

- **`GroupId`** type (`src/id.rs`): `group-<ULID>` `generate()`, `as_str`,
  `Display`, `FromStr` (empty rejected), serde.
- **`RegistryEntry.group: Option<GroupId>`** with
  `#[serde(default, skip_serializing_if = "Option::is_none")]` — legacy registry
  JSON (no `group`) still loads; ungrouped JSON is byte-unchanged.
- **Assignment**: `--group` global flag (`RunArgs`) + `[runtime] group` config
  key; `Config::resolve_group` precedence `--group > [runtime] group > None`,
  applied in `run` and `run_headless`.
- **Inheritance**: `spawn_detached` passes `--group` into the child `serve`
  argv; `/spawn` inherits `ReplState.group`; the `spawn` tool inherits
  `ToolCtx.group` (from `Agent.group`) unless its own `group` arg overrides.
- **Recognition**: `agent-cli list [--group <id>]` — a `GROUP` column + filter;
  `agent-cli groups` — detects the distinct running groups (aggregating the live
  `list_entries`, so a group appears iff a member is alive) via a pure
  `aggregate_groups` seam, printing `GROUP / MEMBERS / AGENTS`.
