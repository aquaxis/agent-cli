## 3. Deviations from the design (D-1 – D-4)

1. **Lineage is an ancestor chain, not `parent` + `depth`.** Writing the first
   test of an orphaned descendant showed the flaw: when an agent in the middle
   exits, `list_entries` prunes its file, and with only a parent id its children
   become unattributable — the design's own AS-09 could not hold. The full chain
   also turns `descendants_of` from a walk into a filter.
2. **The subtree rule is a separate pure function** (`stop_permission`). The
   first test suite called the tool on an *allowed* target; because the fixtures
   register this process' own pid, `stop_peer`'s SIGTERM fallback killed the test
   runner. The rule is now a table in a test, and the allowed path is covered by
   the real-tree integration test.
3. **`list_agents` names the intermediate agent** for a deeper descendant
   (`descendant (via reviewer)`, and `no longer running` when that agent has
   exited): the distance alone does not tell the model which of its children owns
   a grandchild.
4. **`ToolCtx` carries the chain** rather than a depth (the depth is its length),
   and `SpawnLimits` gained a `Default` so the nine existing tool test fixtures
   needed one line each.

## 4. Verification

- `cargo build` clean. `cargo test`: **473 unit + 3 integration, 0 failed**
  (454 at the v0.15.0 baseline) — 19 new tests.
- `cargo clippy --all-targets`: back to exactly the v0.15.0 warning set.
- **Real agents**, in one session: the agent spawned `worker`, listed it
  (`depth=1  child`), was refused a second spawn —
  `child limit reached: 1 live child agent(s) and [spawn] max_children is 1` —
  stopped `worker` with `stop_agent`, spawned `third` into the freed slot, and
  listed it.
- **The subtree rule in practice**: a fresh session's `list_agents` answered
  `no agents below this one` while `agent-cli list` showed a peer left by the
  previous session — an agent sees only what it created.
- **Non-regression**: `spawn` / `list` / `list --group` / `groups` / `stop`
  output is identical to a **v0.15.0 binary** built from the release tag (ids,
  pids and timestamps normalised), and a registry file written by that binary —
  with no `ancestors` key — is listed and stopped by the new one, leaving the
  registry empty.
- The integration test builds a real two-level tree, checks the recorded chain,
  stops the middle agent and confirms the grandchild keeps running and stays
  attributable, then stops everything and asserts no process survives.
