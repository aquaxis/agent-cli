## 3. Implementation

### T-02 — `src/select.rs`

`Point`, `Selection` (`begin` / `extend` / `normalised` / `is_empty`),
`row_span`, `highlight` and `selected_text` — all pure, no terminal, no
reference to `app.rs`. Two deviations, both towards reuse: `theme::strip_sgr`
already did what design §3.4 called `scroll::plain_text` (it was test-gated and
is now production code), and instead of a second slicer beside `visible_rows`,
that function became `marked_rows`, returning `scroll::Row { text, continues }`
— the row and whether it continues the line above, which is exactly the fact
needed to undo the wrap.

### T-03 — the gesture (`src/app.rs`)

Three arms in the event drain, guarded by `state.scroll && state.mouse_select`
and skipping any event carrying `SHIFT` so a shifted drag is left to the
terminal. The indicator-toggle arm keeps priority on a **hit** and now falls
through on a miss, so a drag on the log during a turn still selects.

The live selection lives on `ScrollOverlay` rather than in the input loop
(deviation from §4): the overlay is what `draw_scroll_overlay` already receives,
so the highlight cost no signature change anywhere. Two supporting extractions:
`bottom_block_rows` (the pinned-block height the wheel arm had inline) and
`body_slice_at` (the padded body slice **both** the drawing and the copy read,
so the highlight and the clipboard cannot disagree about which row is which).
The overlay takes the screen while a drag is live even at offset 0, which is how
a selection in the live view gets a highlight the terminal cannot draw.

### T-04 — `src/clip.rs` and the switches

A 20-line base64 (no new dependency), `osc52` with tmux passthrough under
`TMUX`, and `copy` returning `Sent` / `Empty` / `TooLarge` / `Failed`. The
terminal write is injected as a closure, so tests see exactly what would reach
the wire. `[ui] copy_command` is piped to through `sh -c` and its failure is
reported, **never** retried through OSC 52. `OSC52_LIMIT` is 74 000 bytes,
refused rather than truncated. `[ui] mouse_select` and `[ui] copy_command` were
added to `UiConfig` and both config templates. `Role::Selection` was added to
the palette table, since `theme.rs`'s rule is that call sites name a role and
never a colour.

The interactive verification was driven by a **pty harness** rather than by hand
(deviation from §8/C-05): it forks a pty, sizes it to 24×80, feeds the REPL real
SGR mouse reports and decodes the OSC 52 payload agent-cli wrote back — which is
repeatable and can assert the exact bytes on the wire.

| Case | Result |
|---|---|
| Drag in the live view | `\x1b[7m` on the wire while dragging; on release an OSC 52 whose decoded payload **is the selected text** — 430 bytes, 14 lines, no escape sequence in it |
| Mid-row to mid-row, two rows apart | `"OW4 the quick brown fox\n$ echo ROW4 the"` — both ends cut exactly where the pointer was |
| Scrolled back (two wheel notches first) | Copied rows from further up the log, highlighted the same way |
| A click, no drag | `[clip] nothing selected`; nothing written |
| `mouse_select = false` | No highlight, no copy, no feedback; the wheel still scrolled |
| `copy_command = "cat > file"` | The file received the text, **no** OSC 52 was written, the line named the command |
| Blast radius | The piped loop, `agent-cli list` and `--help` behave as at v0.18.0 |

Hygiene: every pty session exited with `/quit` and left no agent behind; the
clipboard was never read, and the only thing written to it was the harness's own
selection.
