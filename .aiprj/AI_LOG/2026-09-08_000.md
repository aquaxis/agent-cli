## 2. What was built

While a turn runs, an interactive REPL now shows the line being executed on a
single terminal row (cut with `…`) and, directly beneath it, a row redrawn in
place carrying a spinner and the elapsed time. When the turn ends that row
becomes one permanent `✔ <elapsed>` line (`✗ <elapsed>` after an error).

```text
> explain how the cancellation path works end to end
[tool-call] bash {"command":"sleep 4"}
⠼ 2.3s
```

```text
[answer]
the answer
✔ 5.2s
>
```

- `AgentEvent::TurnStart` marks the turn boundary; it prints nothing.
- `StatusIndicator` (`src/app.rs`) owns the bottom row: painted only from
  column 0 of a fresh row, erased with `MoveToColumn(0)` +
  `Clear(FromCursorDown)` before anything else is written, cut to
  `terminal_width - 1` columns so it can never wrap.
- The display task is a `select!` over the event channel and a 100 ms tick, so
  the spinner turns between events.
- While the indicator is on, `display_event` prints the `[tool-call]` line cut
  to one row, so it is both the activity line and the scrollback record.
- The indicator is shared with the raw input loop as `Arc<Mutex<..>>`; the loop
  suspends it before printing `[cancelled]`, the approval prompt, or on
  shutdown, and resumes it when the approval answer returns to `Pending`.
- `[ui] show_progress` (default `true`) turns it off; it additionally requires
  stdin and stderr to be terminals, so piped output and `serve` are unchanged.
