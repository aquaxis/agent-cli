This session follows an investigation the user asked for immediately before,
into whether agent-cli can launch and manage child agent-cli processes. The
answer was that **creation and messaging already exist** (`spawn`, `send_to`,
the registry, IPC, groups — all verified by running them) and that the
management half is what is missing. The instruction targets exactly that gap.

## 3. Findings that shaped the specification

- **Creation is a tool, management is not.** The model has 11 tools; none lists
  or stops a peer, so its only route is `bash` running `agent-cli stop` — and an
  agent configured without `bash` cannot stop what it created at all (BL-06).
- **A child inherits the parent's config file** (BL-09), so a `spawn`-enabled
  agent produces `spawn`-enabled children, and a `grep` for depth/count guards
  finds nothing anywhere in the tree (BL-10). Autonomous creation is currently
  unbounded in both breadth and depth.
- **The registry has no lineage** (BL-03): `RegistryEntry` knows nothing about
  who created whom, so "my children" is not answerable today. That is the one
  new piece of state the cycle needs — and `group`, added the same way with
  `#[serde(default)]`, is the precedent for adding it compatibly.
- **A peer auto-approves its own tool calls** (BL-08), because headless has no
  console. That is unchanged here, and it is precisely why the bound matters.

## 4. Key decisions

| Decision | Reason |
|---|---|
| Lineage as `parent` + `depth` on `RegistryEntry`, both `#[serde(default)]` | Any agent sharing the registry can read the tree, a parent's exit does not lose it, and files written by v0.15.0 still load (FR-01, FR-02, P-1, P-6). |
| Carried to the child through **environment variables**, not a new CLI flag (AS-01) | The instruction forbids changing the CLI subcommands' behaviour; the argument vector therefore stays byte-identical. |
| `stop_agent` may stop **only the caller's own subtree** (AS-03) | It is what the instruction is about ("cannot stop what it started"), and it is what makes the tool safe enough to ship enabled by default while `spawn` stays opt-in. Humans keep the unrestricted `agent-cli stop` / `/stop`. |
| The limits bind **the `spawn` tool only** (AS-04) | The instruction protects the CLI's behaviour, and the runaway risk is the autonomous path. A human who types `spawn` has decided to. |
| The policy is a **pure function** `spawn_allowance(live, depth, limits)` | The whole truth table becomes a unit test and the enforcement point keeps no state (NFR-03). |
| Deny with a **tool error naming the limit, its value and the current count** (FR-10) | The model can adapt — stop a child, or stop trying — instead of retrying blindly. |
| `[spawn] max_children = 4`, `max_depth = 2` | Enough for real delegation (a root with four workers, each able to delegate one level), small enough that a loop is stopped within seconds. `0` for either switches autonomous spawning off. |
| Live children counted from the registry at check time | A child that exited frees its slot for free, because `list_entries` already prunes dead peers (BL-04). |
