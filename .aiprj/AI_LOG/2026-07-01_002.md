### Step 2 — Analyze current REPL command dispatch (`src/app.rs`)

- `handle_repl_command(rest, &input_tx, &state, raw_mode) -> bool` is the
  central dispatch function (line 1312–1389).
- It splits `rest` into `cmd` + `arg` and matches `cmd` against a fixed set:
  `quit`, `exit`, `help`, `auto`, `clear`, `reset`, `history`, `list`, `send`,
  `tools`, `persona`, `reload-persona`, `peer`, `cancel`. Unknown commands
  print `unknown command: <cmd>`.
- Two call sites: `run_input_loop_raw` (line 887) and `run_input_loop_line`
  (line 1057). Both check `if !handle_repl_command(...) { break/exit }`.
- `ReplState` holds: `registry_dir`, `agents_dir`, `persona_file_setting`,
  `cli_persona_path`, `name`, `persona`, `tool_names`, `history_path`,
  `history`, `auto_approve`.

### Step 4 — Analyze `.claude/commands/*.md`

- Files: `ai.md`, `setup_ai.md`, `update_ai.md`, `close_ai.md`, `next_ai.md`.
- Format: content is either a literal prompt text or a `@file` reference (e.g.
  `@.aiprj/rules/exec_job.md`). Claude Code expands `@file` to the referenced

- This confirms the design approach: `.md` file content → expanded prompt →
