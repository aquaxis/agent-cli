## 3. Deviations from the design (D-1 – D-4)

1. **The pinned block during a turn is the spinner row, not the prompt.** During
   `Pending` the live screen has no prompt and keys other than the cancel keys
   are ignored, so pinning `> ` would have invited input that is not accepted;
   the spinner is what the bottom row would be showing anyway, and it tells the
   reader the turn is still going.
2. **The scrolled screen is redrawn on a timer** (100 ms while a turn runs, 1 s
   otherwise) and each draw clears row by row instead of clearing the screen —
   the pinned spinner has to live while the indicator's own block is suspended,
   a peer's prompt can write underneath the overlay, and per-row clearing does
   not flicker.
3. **`theme::strip_sgr` / `has_sgr` stayed `#[cfg(test)]`** — `wrap_styled`
   measures columns as it scans, so no production code needs them.
4. **`print_header` was routed through `raw_println`** so the banner is part of
   the log; it printed with `println!` directly and the wheel therefore stopped
   one screen short of the top. It runs before raw mode, so its bytes are
   unchanged. Two other pre-existing direct `println!` calls (one `/help` line,
   the `/peer` listing) were deliberately left alone.

  elapsed times and spinner frames) with no mouse reporting; piped stdin/stdout

  but the wheel untouched, the only difference is the mouse-reporting enable
