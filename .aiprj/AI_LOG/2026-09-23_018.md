## The diagnosis

All measurements taken 2026-09-23 against the installed v0.20.0 binary and
confirmed on the 0.21.0 debug build; temporary directories under `/tmp` with
isolated `HOME`.

- **Reproduced byte-exactly**: `error: toml parse error: duplicate field
  'bash' in 'tools'`, exit 1.
- **Cause**: `ToolsConfig.bash` carries `#[serde(default, alias = "shell")]`
  (`src/config.rs:477`–`:482`; the shell→bash rename shipped v0.9.0, commit
  `5f7df99`). serde's derived `Deserialize` rejects a table carrying **both**
  spellings of one aliased field, and the error names the canonical field.
- **Why layering produces it**: the v0.20.0 merge (`merge_at`,
  `src/config.rs:943`–`:985`) matches keys by name on `toml::Value`, before
  deserialization and blind to aliases. A base file with `[tools.bash]` plus
  an overlay with `[tools.shell]` deserialize as one table holding two fields
  for one struct field.
- **The failing matrix**: base bash + overlay shell (the reported shape);
  the reverse order via two `--config` occurrences; one file carrying both
  headers (identical values included). The sibling alias fails identically:
  `defaultMode`/`default_mode` → `duplicate field 'default_mode' in
  'permissions'`, both orders.
- **Controls**: each spelling alone loads — alias-only, canonical-only, the
  same spelling in both layers. The alias is honest in isolation.
- **Command matrix on a broken directory**: `run`, `doctor`, `list`,
  `providers` all exit 1 — `doctor` cannot start, the diagnostic is dead
  exactly where it is needed. `config path` exits 0 (exposes the offending
  overlay); `update` exits 0 (dispatch precedes the config load — the upgrade
  path out).
- **Remedies, executed**: renaming the legacy header to the canonical spelling
  makes the chain load with the overlay's permissions intact; `--config <user
  file>` bypasses the overlay and runs cleanly at the cost of the overlay
  entirely (`config explicit : true`, `0 deny, 0 allow`).
- **Provenance**: aiprj never shipped a `[tools.shell]` template — its
  `.agent-cli/config.toml` began at aiprj v1.1.0 (commit `e272d43`, 2026-09-20)
  already with `[tools.bash]`; a history search of the aiprj repository for
  `tools.shell` returns nothing. Only two project overlays exist on this
  machine (ChronoMark, aiprj); both are canonical and both load. The
  directory that triggered the report is not on this machine, but the
  mechanism is directory-independent.
- **Exposure window**: v0.19.0 read exactly one file, so the two spellings
  could never meet; the failure shipped with layering (PR #21, v0.20.0), not
  with the alias (v0.9.0).
- **Alias inventory**: `tools.shell`→`tools.bash` and
  `permissions.defaultMode`→`permissions.default_mode` are the only two TOML
  aliases; the third serde alias, `wait_reply`, is tool-call JSON — out of
  scope.
- **Baseline**: `cargo test` green at 565 unit + 6 integration in a default
  parallel run; `clippy --all-targets` at 8 pre-existing warnings (1
  empty-line-after-doc, 2 collapsible `if let`, 2 `map_or`, 3 `&PathBuf`).
- Noted and left alone: a legacy `"shell"` entry inside `[tools] enabled` is
  not alias-resolved (it silently fails to enable bash) — pre-existing
  behaviour, not part of this failure, recorded as out of scope.
