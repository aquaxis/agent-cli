## Actions Taken

### Task 8 — Extra blank line before `[answer]` (Defect #7, FR-15)
- **Root cause**: the Defect #5 echo fix made `PromptRenderer::finish_line` end
  the echoed input line with CRLF, while the first display section header was
  printed with a leading newline (`raw_eprintln(rm, "\n[answer]")`). The two
  newlines produced a blank line between the input and `[answer]`.
- **Fix** (`src/app.rs`): added `DisplayState.section_printed` (reset in
  `reset()`, which already runs on `Done`/`Error`) and a pure
  `section_header_text(label, section_printed)` helper used by a new
  `DisplayState::section_header()`. `[answer]`, `[thinking]` (collapsed and
  expanded), and `[tool-call]` now emit via `section_header`, so the first header
  of a turn has no leading newline (sits directly under the echoed input) and
  subsequent headers keep it (preserving thinking→answer separation). `[error]`,
  `[tool-result]`, `[info]` left unchanged.
- **Tests**: `first_section_header_has_no_leading_newline`,
  `subsequent_section_headers_keep_leading_newline`,
  `display_state_section_flag_resets_each_turn`.

### Task 9 — Ollama 503 root-cause investigation (FR-11, FR-12)
- Confirmed by source inspection that **no `:cloud` tag stripping exists**
  anywhere (`grep` for `split`/`strip_*`/`trim_*`/`:cloud` over `src/` finds only
  the unrelated `/`-trim on `base_url`). `OllamaProvider::complete_stream` sends
  `self.model` verbatim. The `glm-5.2` in the error is Ollama's cloud backend
  reporting the base model name.
- The real difference from `ollama run`: the `ollama` provider had **no retry**
  (whereas `src/ai/opencode.rs` already retries a recoverable error). A transient
  cloud cold-start/overload 503 was surfaced immediately. → fix = bounded
  retry-with-backoff.

### Tasks 10 & 11 — Verbatim model name + bounded retry (FR-12, FR-13, FR-14, NFR-05)
- `src/ai/ollama.rs`:
  - Extracted pure `build_chat_body(model, messages, tools, temperature)` (keeps
    the model name, incl. `:cloud`, verbatim).
  - Added pure `is_transient(status, body)` — true for HTTP 503/429/500/502/504
    or a body containing `overloaded`/`temporarily`/`please retry`/`try again`
    (case-insensitive).
  - Added pure `backoff_delay_ms(attempt)` — 1s/2s/4s, capped at 8s, overflow-safe.
  - `complete_stream` now wraps the initial POST + status check in a bounded loop:
    success → break; transient HTTP error within `max_retries` → backoff + retry;
    non-transient or exhausted → surface the existing rich `ProviderError`
    unchanged; transient network errors (timeout/connect) also retried. Each
    retry logs attempt/status/delay. Only the initial request is retried — not a
    stream already yielding events.
  - Added `max_retries: u32` field (default `DEFAULT_MAX_RETRIES = 3`, `0`
    disables).
- `src/config.rs`: added `[provider.ollama] max_retries: Option<u64>` to the
  shared `ProviderEntry`.
