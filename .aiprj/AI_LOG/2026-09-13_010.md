## 3. Implementation

### T-03 — the headers (`src/ai/opencode.rs`)

- `OpenCodeProvider` gained `session_id`, set in `from_config` from
  `[provider.opencode] session_id` or a fresh `ses_<lowercase ulid>`, commented
  against `PersistState::id` so the gateway routing id and the local server
  session are not confused.
- `CloudRequest { url, headers, body }` and `build_cloud_request(api, messages,
  tools)` were extracted from the two `complete_stream_cloud_*` methods, which
  are now build-apply-send around the unchanged parsers. Headers: the existing
  `content-type` / `authorization` / `x-api-key` / `anthropic-version`, plus
  `x-opencode-session` and `user-agent: agent-cli/<CARGO_PKG_VERSION>`.
- The local handshake was not touched.

### T-04 — the Go defaults (`src/config.rs`)

`apply_opencode_go_defaults` now fills `api = "openai"` and
`model = "qwen3.8-max"` (confirmed served by `GET
https://opencode.ai/zen/go/v1/models` on 2026-09-13, recorded with that date in
the doc comment). `base_url`, `api_key_env`, the fill-only-`None` rule and the
kind normalisation are unchanged. `ProviderEntry` gained
`session_id: Option<String>`; `DEFAULT_CONFIG` and
`example/config.example.toml` gained commented `model` / `session_id` lines with
the open-weight-catalogue note.

### T-05 — the hints (`src/ai/mod.rs`)

Two rules ahead of the `401` rule: one for `MissingSessionID` /
`x-opencode-session`, one for a model the endpoint does not serve. The session
hint says "older agent-cli builds" rather than naming a version, which would go
stale at the next release. The `401` rule is unchanged.

### T-06 — tests

Eleven new tests; suite now **491 unit + 4 integration, 0 failed** (480 + 4 at
the baseline). Covered: both cloud surfaces' headers, URL and body; session id
stability and uniqueness; a configured id used verbatim; no invented auth header
without a key; the refreshed defaults, preserved explicit values and a
non-`claude-*` default; `session_id` parsing; both hint corrections.

**Deviation from design §7**, which said all tests would be pure: two
`#[tokio::test]` cases bind a `std::net::TcpListener` on port 0 and capture one
request's header block. A pure test cannot prove the *negative* the design asks
for — that the local handshake carries neither header — because the local path
builds its own requests. No new dependency; recorded in `AI_PRJ_DESIGN.md` §10.2.

### T-07 — documentation

`doc/providers/opencode.md` (new "Session id (`x-opencode-session`)" section,
the catalogue note, corrected Go examples, two troubleshooting rows),
`doc/config.md` (the `session_id` key, the corrected `opencode-go` defaults row
and alias description), `doc/troubleshooting.md` (a `HTTP 400 MissingSessionID`
section with the distinguishing `curl`, and the `ModelError` entry corrected),
`README.md` / `README_ja.md` (Go defaults and the session id; still 25
`##`+`###` headings each), `CHANGELOG.md` (`[Unreleased] → Fixed`, three
entries). All relative links resolve.
