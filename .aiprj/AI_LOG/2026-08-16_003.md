### T-06 – T-10 — `report_wrapper.md`

Created `report_wrapper.md` (Japanese, following `report_command.md`
conventions) with the thirteen sections of design §11: 概要 / 結論 /
agent-cli の現状 / 既存 provider "claude" との違い / Claude Code 側の接続口 /
接続方式の候補 / ProviderEvent へのマッピング / 実装時の変更点 / 比較表 /
リスクと制約 / 推奨方式と段階的な実装案 / 付録.

Verdict: feasible with conditions. Recommended shape is the resident
subprocess with bidirectional stream-json, reached in four stages starting from
the one-shot print backend. Everything in the recommendation is labelled as a
proposal; nothing was implemented.

Two findings shaped the analysis more than the plan anticipated:

1. The `stream_event.event` payload is Anthropic SSE, so the existing parser
   `src/ai/claude.rs:283` can be reused after one level of unwrapping.
2. `tool_use` blocks are emitted *after* Claude Code has already run the tool,
   so mapping them to `ProviderEvent::ToolUse` would execute every command
   twice. This is what makes the gateway/delegation choice mandatory rather
   than stylistic.
