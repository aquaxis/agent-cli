## 2. What was built

The REPL is now colour-coded. On screen:

```text
agent-cli ready                                   ← magenta bold
  provider  : ollama (smoke)                      ← dim
> check the build                                 ← cyan bold + bold
[tool-call] bash {"command":"sleep 2; echo …"}    ← cyan bold + grey
[tool-result ok] bash: {"exit_code":0,…}          ← grey dim
[answer]                                          ← magenta bold
the answer body                                   ← not coloured
⠹ 12.4s                                           ← grey dim
  reasoning line …                                ← grey dim
✔ 3.1s                                            ← green bold
```

- **`src/theme.rs`** (new) holds the whole palette as `Role` → (ANSI 16
  foreground, attributes), plus the pure `paint(role, text)` which wraps a
  string in the SGR sequence and closes it with a reset. 17 roles, one per
  element that the display actually renders.
- **Enablement** is `ColorMode { Auto, Always, Never }` from the new
  `[ui] color` key, resolved by the pure
  `resolve(mode, is_tty, NO_COLOR, TERM)` **once per stream at startup** into a
  `Copy` `Theme { stdout, stderr }`. `Theme::out` / `err` return
  `Cow::Borrowed` unchanged when that stream has no colour.
- **Application** is at the print sites in `src/app.rs`: `display_event`,
  `StatusIndicator`, `PromptRenderer`, the approval / cancel / `[auto]` /
  banner / `/history` paths. `AgentEvent::Text` is never styled.

Two invariants keep it safe next to the existing display maths:

1. **Paint last.** `str_display_width`, `truncate_display` and `wrap_display`
   count every character, so every line is measured, cut and wrapped *before*
   it is styled, and `PromptRenderer` keeps computing its cursor column from
   the plain prompt and buffer.
2. **One sequence per row.** Multi-row output (`style_rows`, the indicator's
   block) is styled row by row, and a separating newline always stays outside
   the sequence, so a colour never spans a line break that may later be erased
   and redrawn.

## 3. Decisions worth recording

- **The answer body is not coloured**, as the instruction says. It is also what
  keeps streamed `Text` deltas free of any per-chunk styling state.
- **Per-stream enablement.** stdout and stderr are judged separately, so
  `agent-cli run > answer.txt` from a terminal writes a clean file while the
  status display on screen keeps its colour.
- **The spinner is grey, not magenta** (the instruction allows either), leaving
  magenta to mark the two brand elements — the answer marker and the banner.
- **`NO_COLOR` applies to `"auto"` only.** `"always"` is the user's own explicit
  instruction in their own config file and overrides it.
- **`Role` has no entry without a call site**, so the instruction rows the
  display cannot render add no dead code.

## 4. Out of scope (recorded, not implemented)

- **AS-01** — the instruction's table describes a fuller TUI than agent-cli
  renders. Markdown headings/emphasis, inline code, code blocks, links and file
  paths, diffs, separators, a warning class and token counters have **no
  counterpart in the current display**: there is no markdown parser, no syntax
  highlighter and no diff view to attach a style to. Each needs a *renderer*
  first, which is a feature rather than a colour change. Recorded in
  requirements §4.2.
- **AS-02** — no theming, no per-role configuration, no 256-colour/truecolour.
- **AS-03** — no background colour and no `reverse`.
- **AS-04** — the REPL only: `src/commands.rs`, `src/update.rs`, the IPC layer
  and the conversation log are untouched. The `tracing` logger colours its own
  lines and follows `NO_COLOR` on its own; that layer is outside this cycle and
  is now noted in `doc/troubleshooting.md`.
- **AS-05** — no line's text, order or destination stream changed.

- `cargo build` clean; `cargo test` **406 unit + 2 integration, 0 failed**
  (389 unit before); `clippy --all-targets` shows only the eight pre-existing
  warnings, none in new code.
- PTY smokes against a stub Ollama-shaped provider confirmed every colour of
  §2 plus `[tool approval]` / `approve? [y/N]:` (yellow bold), `[cancelled]`
  (dim grey), `[error]` and `✗` (red bold), each row self-closing.
- Compared against a **v0.11.0 binary built from a git worktree at the release
  commit**: `color = "never"` is byte-identical; piped stdin/stdout is
  byte-identical on both streams; `serve` is identical even with
  `color = "always"`; `TERM=dumb` writes no SGR. On a 40-column terminal with a
  CJK question the drawing is identical once the sequences are stripped, so
  truncation, wrapping and the cursor column are provably unaffected.
- `color = "always"` with both streams piped does write colour.

## 6. Deviations from the design

1. `Theme` is stored as a `Copy` field on `ReplState` rather than threaded
   through the input-loop signatures — that is what keeps those signatures and
   their test call sites unchanged (design §6).
2. `PromptRenderer::render` / `finish_line` take a `Role` in addition to the
   theme: the loop has two prompts, the input prompt (cyan) and the approval
   prompt (yellow), and passing the role is exact where inferring it from the
   prompt string would be guesswork (design §6.3).
3. `style_rows` was generalised from the tool result to `[info]` and `[error]`,
   which can carry a newline just as well (design §6.1).
4. Inside the indicator's block the reasoning rows are told apart from the
   status row and the marker by their two-column indent, which keeps
   `thinking_rows` plain and its tests untouched. Both roles map to the same
   SGR parameters, so the distinction is nominal (design §6.2).
5. `strip_sgr` / `has_sgr` live in `src/theme.rs` under `#[cfg(test)]` so both
   modules share one CSI-aware implementation (design §3).

All five are reconciled in `AI_PRJ_DESIGN.md` and `AI_PRJ_TASKS.md`.
