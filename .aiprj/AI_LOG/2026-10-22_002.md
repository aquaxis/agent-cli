## 2. What happened this session

- **Field defect 1 (v0.30.1)** — the user's report: `agent-cli
  --provider strata` died with
  `provider error (codex): env var OPENAI_API_KEY not set`. Root cause:
  `apply_strata_defaults` built the alias **on top of the user's
  `[provider.codex]` table** (`api_key_env = "OPENAI_API_KEY"` inside),
  so the "keyless" alias inherited the codex key and failed at the OpenAI
  key gate. Repair: the alias composes from `[provider.strata]` plus the
  keyless strata defaults only — no field of a codex table may leak in
  (`strata.take().unwrap_or_default()` as the base). Pinned by
  `strata_alias_never_inherits_the_codex_table_s_key`, fold-verified
  (re-inherit → FAIL). Shipped as v0.30.1 (`70e6b5b`), released, binary
  installed; `selftest --provider strata` passed all five stages against
  the live engine.
- **Field defect 2 (v0.30.2, this session's user ask)** — "strata
  start → show the provider as **strata**". The v0.30.0 design rewrote
  the kind in place (`strata → codex`) so every display read `codex`.
  Repair: the kind is **kept** —
  - `apply_strata_defaults` fills only the **strata slot** (defaults
    minus key material) and the kind stays `"strata"`; the codex table
    is never read (the v0.30.1 fix is now structural);

  Pinned by `strata_configured_reports_strata_everywhere_codex_reports_
  codex` (name + error prefix both read `strata`), fold-verified
