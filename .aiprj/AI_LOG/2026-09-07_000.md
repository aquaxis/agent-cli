## 2. What was built

`Esc` (and `Ctrl-C`) pressed while the agent is working now forcibly returns the
user to the prompt.

- **`CancelToken`** (`src/agent.rs`): `AtomicBool` + `tokio::sync::Notify`, with
  `cancel` / `is_cancelled` / `reset` / `cancelled()`. `cancelled()` registers the
  `notified()` future before re-checking the flag, so a cancellation raised just
  before an await is never missed. Held as `Arc` on `Agent` (`pub cancel`) and on
  `ReplState`, alongside an `Arc<AtomicUsize>` suppression counter.
- **REPL** (`src/app.rs`): during `Pending`, `is_cancel_key` → `begin_cancel`
  (raise the token, count the draining turn) → print `[cancelled]` → `Ready` →
  redraw. The prompt never waits for the agent. `Esc` at the approval prompt also
  denies the pending `oneshot`. `/cancel` raises the same token. `handle_key` and
  the idle-prompt key meanings are untouched.
- **Agent** (`src/agent.rs`): `process_turn` resets the token at entry and observes
  it at the tool-iteration boundary, in a `biased` `select!` against
  `stream.next()` (the stream is then dropped, ending the response body read), and
  in a `select!` against `tool.invoke()` (a running tool is abandoned).
  `finish_cancelled` gives every unresolved tool call a `cancelled by user`
  result — via the new pure `cancel_tool_results` — so the assistant message's
  `tool_calls` stay balanced and the next request is valid, then emits `Info` and
  exactly one `Done`.
- **Display** (`src/app.rs`): the pure `suppression_decision(is_terminal,
  outstanding)` drops every event of a cancelled turn up to and including its
  terminal event, which consumes the cancellation and sends **no** idle
  notification. Because the event channel is FIFO and each turn emits exactly one
  terminal event, this suppresses precisely the cancelled turn's remainder and
  prevents its `Done` from releasing a later turn from `Pending`.

No new dependency; Linux-only as before; an un-cancelled turn behaves exactly as
it did.

## 3. Deviations from the design document

| # | Deviation | Reason | Documents reconciled |
|---|---|---|---|
| 1 | `cancel` / `suppress` are carried on `ReplState` instead of being threaded as two extra parameters through `run_input_loop` / `_raw` / `_line`. | The loops and `handle_repl_command` already receive `&state`; this leaves the signatures and their test call sites unchanged (only two `ReplState` constructors moved). | design §7, R-8 |
| 2 | The key cancel paths do **not** queue an `AgentInput::Cancel`. | The agent reads that message only after the turn has ended, and its `Info { "cancel requested" }` would then print over the freshly drawn prompt. The token alone is the signal; `/cancel` still sends it for the idle case. | requirements FR-02, design §4, new risk R-9 |
| 3 | FR-12's "input-loop-level test that `Pending` + cancel returns to `Ready`" is covered by the PTY smoke plus the `begin_cancel` / `suppression_decision` tests. | The state transition needs a TTY (C-04). | requirements FR-12 |

Two smaller implementation notes were folded into the design: the explicit
`drop(stream)` before `finish_cancelled` (the stream borrows `self.provider`), and
`DisplayState::reset()` when a cancelled turn's terminal event is dropped.
