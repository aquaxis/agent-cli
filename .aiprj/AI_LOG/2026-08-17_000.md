### T-02 – T-07 — The backend (`src/ai/claude_code.rs`, new)

Registered in `ai::build` and `SUPPORTED`. Structure follows `opencode.rs`:
module header, pure helpers, `Provider` impl, tests.

Operating matrix, exactly as `report_wrapper.md` framed it:

| mode / transport | Process model |
|---|---|
| delegation + stream + persistent (default) | One resident child; one JSON line per turn on stdin; only new messages sent |
| delegation + oneshot | One child per turn, `--session-id` then `--resume` |
| delegation + ephemeral | One child per turn, `--no-session-persistence`, transcript re-sent, tools still enabled |
| gateway | One child per turn, `--tools ""`, transcript as the prompt |

Notable implementation points:

- `build_args` and `map_line` are pure functions, so every flag combination and
  every output shape is unit-testable without spawning anything.
- `stream_event` payloads are handed to the existing Anthropic SSE parser
  (`claude::handle_frame`) after one unwrap. Its `Done` is dropped and its
  `done` flag ignored: `message_stop` ends a *message*, and a delegation turn
  contains several. Only `result` ends a turn.
- `tool_use` blocks are never converted to `ProviderEvent::ToolUse`. Claude Code
  has already executed the tool by the time it reports it, so converting would
  run every command twice.
- With `--include-partial-messages` the final `assistant` message duplicates the
  streamed deltas, so it is ignored in that mode and used only in `oneshot`.
- The returned stream carries the session mutex guard, so turns serialise per
  provider — consistent with one-process-one-agent.
- Failure paths (timeout, non-zero exit, unparsable output, stdout closed
  mid-turn, spawn failure) each emit exactly one `Error` then `Done`.
- Children are spawned with `kill_on_drop(true)`; stderr is drained by a
  detached task into a 20-line tail used in error messages.
- The session UUID for `--session-id` is derived from a ULID's bytes with the
  version/variant nibbles forced, so no new dependency was needed.

## Notes and deviations

- **Gateway mode is chat-only, and this was known before coding.** `claude -p`
  accepts no external tool definitions, so agent-cli's tool registry cannot be
  offered to it. This was recorded in the requirements before implementation and
  is documented in the provider doc, `doc/config.md`, and both READMEs.
  Delegation is therefore the default.
- **One design refinement.** `session = "ephemeral"` also disables the resident
  child: a stateful child that is additionally re-sent the whole transcript
  would accumulate a duplicated history.
- **`kill_on_drop` replaced the planned explicit `Drop` impl** — same guarantee,
  less code. Design §6.3 updated.
- **One flaky test, diagnosed rather than papered over.** A stub test
  intermittently failed with ETXTBSY. Cause: the suite runs in parallel, and a
  child forked by one test holds another test's still-open write handle on its
  stub between `fork` and `exec`. The fixture retries; the provider was not
  changed. Verified stable over four consecutive full runs.
- **`cargo fmt` caution.** Running `cargo fmt` reformats the entire crate, which
  has never been rustfmt-clean; that produced a large unrelated diff, which was
  reverted. The new module is rustfmt-clean on its own and each inserted hunk
  was formatted to match.
- **Cost note for unattended use.** `max_budget_usd = 0.20` was exhausted within
  two turns on `sonnet` (a fresh session costs on the order of $0.04), which
  surfaces as `error_max_budget_usd`. Set the cap with headroom.
- Files changed: `src/config.rs`, `src/ai/mod.rs`, `src/ai/opencode.rs`
  (`flatten_history` promoted to `pub(crate)`), `src/commands.rs`,
  `README.md`, `README_ja.md`, `doc/config.md`, `doc/architecture.md`,
  `example/config.example.toml`; added `src/ai/claude_code.rs` and
  `doc/providers/claude-code.md`. No new crate dependency.
