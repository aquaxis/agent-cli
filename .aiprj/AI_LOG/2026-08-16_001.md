## Findings that motivated the addition

- `run_input_loop` is always called with `interactive = true`
  (`src/app.rs:333`); only the raw-mode branch additionally requires
  `stdin_is_tty()`. Piped stdin therefore runs `run_input_loop_line`, which
  still prints approval prompts and reads their answers from stdin.
- Stdin reads are gated on the `Ready` / `AwaitingApproval` states
  (`src/app.rs:1105`), so EOF is observed only after the in-flight turn
  completes — a piped question always receives its full response before exit
  (`src/app.rs:1164`).
- While `AwaitingApproval`, the next line is consumed as the `y`/`N` answer
  (`src/app.rs:1111`); surplus `y` lines are later read as ordinary prompts, and
  EOF with an approval outstanding denies through the shutdown path
  (`src/app.rs:1172`). Hence `--auto-approve-tools` is the supported route for
  tool use in scripted runs.
- Behaviour confirmed against the built binary:
  `printf '/help\n/tools\n' | ./target/release/agent-cli run` executed both
  commands and exited 0 on EOF.
- Documentation search: `README.md` mentions `stdin` only in the termination
  table (`Ctrl+D`), has no pipe or heredoc example, and lists no `ask`
  subcommand. `doc/usage.md`'s only CLI-only use case is `agent-cli send`,
  which returns no response. `doc/architecture.md`'s stdin references are
  internal design notes, not usage.
