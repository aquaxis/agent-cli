## 2. Work plan and execution

1. **T-06 — `/send` delivery options (FR-04)**
   - `Delivery`/`resolve` made `pub(crate)` (`tools/send_to.rs`) so both
     surfaces share the vocabulary; `disambiguate_reply_failure` likewise.
   - New shared helpers in `tools/send_to.rs`: `deliver_report` (report
     with the older-peer fallback to a prompt, everything the tool's
     report branch did) and `PeerAsk` (a background ask runner: resolve,
     bind the one-shot reply socket in a temp dir, send the prompt with
     `reply_to`, await under the 120 s bound, disambiguate on failure).
   - The tool's `invoke` now routes report and ask through those helpers
     (its integration tests kept passing unchanged — and the first draft
     of the runner failed its ask integration test because the result was
     pushed on a channel send that was not awaited; caught and fixed).
   - REPL: `parse_send_args` (pure) accepts the option in either slot
     (`/send bob --report y`, `/send --ask alice x`), maps unknown
     `--words` to the tool's exact error text (dash-keeping), and errors
     with the extended usage line. `send_to_peer` builds per-delivery
     behaviour; the ask returns `CommandResult::SpawnedAsk(PeerAsk)`; the
     raw loop holds it in a loop-local `ask_run` and a dedicated select
     arm prints the outcome (`[peer reply] …` / `[send] …`) the moment it
     is known — a slow peer cannot hold the prompt hostage. The line-mode
     loop (tests / non-tty) waits the runner synchronously.
   - Tests: seven `parse_send_args` cases + a `PeerAsk` runner test with
     the mock-reply peer; tool integration tests flow through the same
     helpers.
2. **T-07 — empty-selection clipboard silence (FR-05)**
   - `Outcome::is_empty` added (`clip.rs`); the copy site in the input
     loop no longer carries an Empty outcome into `copied` — nothing
     prints. Real and failed copies keep their lines. clip.rs contracts
     extended (is_empty, and not a failure either).
3. **T-08 — spinner visibility for IPC-received work (FR-06)**,
   verification-first per AS-04:
   - Evidence chain: IPC server bound at `run` start (`app.rs:265`); the
     forwarder maps `Prompt → AgentInput::PeerPrompt` (`app.rs:440`–
     `:456`); `process_turn` emits `AgentEvent::TurnStart` first
     (`agent.rs:423`); the display task starts the indicator on it
     (`app.rs:564`–`:566`). **Socket-received turns already show the same
     spinner** — no code change needed.
   - The only spinner-less paths are intentional: peer reports run no
     turn (receipt line only); a suppressed/cancelled turn abandons the
     indicator; `serve` is headless. Documented in `doc/usage.md`
     (spinner section + peer-prompt walkthrough).
