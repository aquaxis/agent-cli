## Diagnosis

**The pty harness.** A real `agent-cli run` (debug build) driven through a pty
at 100×30, with a mock `ollama` provider serving a 24-line response so the log
has body rows to select. SGR mouse reports written to the REPL's stdin.
Result: `EnableMouseCapture` at startup; one drag produced
`[clip] copied 16 lines (501 bytes) to the clipboard via osc52`, and the OSC 52
payload decoded to the exact transcript rows under the drag. **The selection,
the row arithmetic and the copy are correct** — a first run that dragged over
the empty padding above a short log produced `[clip] nothing selected`, which
is correct behaviour and a harness trap, not a bug.

**The tmux harness.** tmux attached to a pty; a form emitted from a shell
inside the pane with the payload built at run time (so the echoed command text
can never be mistaken for the sequence); delivery observed on the outer
terminal. tmux 3.6, `xterm-256color`:

| `allow-passthrough` (pane) | `set-clipboard` | wrapped form | bare form |
|---|---|---|---|
| off (default) | off | dropped | consumed |
| off (default) | on | dropped | consumed (forwarded only with an `Ms` terminfo entry, absent here) |
| on | off | **delivered** | consumed |
| on | on | **delivered** | consumed (same `Ms` note) |

`src/clip.rs` emitted **only** the wrapped form inside tmux. tmux ≥ 3.3 has
`allow-passthrough` **off** by default, so a stock tmux drops the only form
agent-cli sends — while the `[clip]` line reports success. That is the
reported defect. (Earlier harness runs produced contradictory rows because the
typed command was echoed back; the discriminator is a raw `ESC` byte before
`]52;c;`, which echo text cannot contain.)

Two adjacent findings recorded, both out of scope: with `mouse_scroll = false`
and `show_progress = true`, a running turn enables capture and the input loop
swallows every mouse event (the terminal's selection is unavailable during a
turn); and an explicit `--config` whose `[provider.<kind>]` table is missing
silently falls back to the built-in defaults — found when the first mock
config was rejected and the REPL quietly came up on the default model.

## Implementation

- `src/clip.rs` — `osc52(text, in_tmux)`: inside tmux the bare form followed
  by the passthrough-wrapped form, one payload; outside tmux the bare form
  alone, byte-for-byte v0.20.0. Module docs carry the measured matrix.
  `in_tmux` is `pub(crate)` so `doctor` shares the detection.
- `src/commands.rs` — `clipboard_report(copy_command, in_tmux)`, pure, pinned
  by three unit tests, printed from `doctor` after the config chain. The
  command route prints one line and suppresses the tmux lines; the section
  never touches `all_ok`.
- `doc/troubleshooting.md` — the "Nothing is pasted after selecting the log
  with the mouse" section rewritten around the measured matrix, `doctor` first,
  the `Ms` check (`infocmp "$TERM" | grep Ms`), the `copy_command` way out.
- `doc/config.md` — the `copy_command` row names the dual-form emission and
  the `doctor` pointer.
- `CHANGELOG.md` — `[Unreleased]`: `Added` (the `doctor` section), `Fixed`
  (the stock-tmux delivery).
