## 3. What was found

`instructions.md` had been **replaced**. The previous cycle (the OpenCode Go
session header) is closed, released as v0.18.0 and merged in PR #19; the new
instruction asks for mouse selection of the log with a copy to the clipboard.

Three findings shape the cycle:

- **The gap is small.** Mouse capture has been on for the whole session since
  v0.14.0 so the wheel can scroll, which means `Drag` and `Up` reports already
  arrive — and are discarded at a `continue` in the event drain. Nothing new has
  to be enabled (BL-01, BL-02).
- **The material already exists.** `src/scroll.rs` holds every printed line,
  wraps it SGR-aware, and slices it per viewport, all pure and unit-tested
  without a terminal. Copying from the *transcript* rather than the screen is
  what makes a wrapped line paste as one line and keeps escape sequences off the
  clipboard (BL-03, BL-04).
- **The clipboard route is forced by the environment.** There is no `wl-copy`,
  `xclip`, `xsel` or `pbcopy` on this machine and `DISPLAY` is a forwarded X11
  display under a VS Code terminal, so a subprocess clipboard would not work
  here at all. OSC 52 — which puts the text on the clipboard of whoever is
  *looking at* the session — has to be the default (BL-10), and it cannot be
  acknowledged (BL-11).

A fourth finding is recorded as work rather than as a footnote: four places tell
the user that selecting text needs `Shift` (`doc/usage.md` twice,
`doc/config.md`, and the `mouse_scroll` doc comment in `src/config.rs`). They go
stale the moment this ships (BL-08).

## 4. Decisions taken into the specification

- The transcript, not the screen, is what gets copied (P-1): the wrap is undone,
  the styling stripped.
- The live view is highlighted by drawing the identical slice on the alternate
  screen — the mechanism the wheel scrollback has used since v0.14.0, not a new
  one (AS-05).
- A drag burst repaints **once** per drain, exactly as a wheel burst does
  (P-5, NFR-03).
- An over-sized selection is **refused with its limit named**, never truncated:
  OSC 52 returns nothing, so a half-copy would be indistinguishable from a whole
  one (P-4).
- Selection gets its own `[ui] mouse_select`, so it can be turned off without
  losing the wheel, and `[ui] copy_command` is the escape hatch for terminals
  that refuse OSC 52 (FR-08).
- Out of scope and stated as such: keyboard copying, double/triple-click word
  and line selection, selecting the prompt block, and pasting (AS-01 – AS-04).
