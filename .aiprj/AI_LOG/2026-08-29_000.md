## Summary

Added the **Streamable HTTP** transport to agent-cli's MCP client per
`AI_PRJ_REQUIREMENTS.md` / `AI_PRJ_DESIGN.md` / `AI_PRJ_TASKS.md` (FR-01 – FR-10).
MCP servers can now be reached over HTTP (a URL), in addition to stdio.

- **`src/mcp/client.rs`** — introduced an `McpTransport` seam. `McpClient` is now
  transport-agnostic (holds `Box<dyn McpTransport>` + `next_id` + `timeout`); the
  handshake / `tools/list` / `tools/call` logic is shared. The existing stdio
  logic (child, piped stdin, reader task routing replies by `id`, `Drop`-kill)
  moved verbatim into `StdioTransport`. `connect` dispatches on `server.transport`
  (`stdio` default, case-insensitive). `call` re-adds the `"{method}: …"` error
  prefix so stdio messages are unchanged.
- **`src/mcp/http.rs`** (new) — `HttpTransport` implements MCP Streamable HTTP:
  POST JSON-RPC to `url` with `Accept: application/json, text/event-stream`;
  branch on the response `Content-Type` (JSON → one message; SSE → frames via the
  shared `SseAccumulator` → messages), select the reply matching the request
  `id`. Captures `Mcp-Session-Id` (from any response header) and the negotiated
  `protocolVersion` (from any result) and echoes them on later requests; sends
  static `headers` + an `api_key_env` Bearer; whole op bounded by
  `init_timeout_ms`; `Drop` fires a detached best-effort `DELETE`.
- **`src/mcp/proto.rs`** — three new pure helpers: `sse_frames_to_messages`,
  `select_reply_by_id`, `http_request_headers` (+ a shared `reply_from_value`).
- **`src/config.rs`** — `McpServerConfig` gained `url`, `headers`, `api_key_env`
  (http); `command` relaxed to optional (validated for stdio at connect);
  `DEFAULT_CONFIG` gained a commented `http` example.

**Scope honoured:** client only; single-endpoint **Streamable HTTP** only.
Reuses `reqwest` + `SseAccumulator` — **no new dependency**. Additive: stdio
servers and configs with no `http` server are unchanged;
`connect_all`/`probe_all`/`mcp list`/`doctor` needed **no change** (dispatch is
inside `McpClient::connect`).
