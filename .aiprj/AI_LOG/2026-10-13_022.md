## 3. Survey (T-01)

Measured against the tree before anything changed; recorded as BL-01 – BL-10 in
requirements §3. What decided the design:

- **The resolver is one function with four steps** (`src/persona.rs:141`–`:185`):
  `--persona` → `[runtime] persona_file` → `<agents_dir>/<name>.md` → built-in
  default. No project-local step existed; nothing in the tree read
  `.agent-cli/persona.md`.
- **`.agent-cli/` already is the project-local convention**: the `config.toml`
  overlay (exists-gated, absolutized — `src/config.rs:885`–`:897`) and the
  `.agent-cli/commands` default. The instruction's path is this pattern's next
  member, so the helper mirrors `local_path` / `local_path_in`.
- **Three call sites, all in `src/app.rs`**: `run` (`:221`), `run_headless`
  (`:647`), `/reload-persona` (`:3983`, reading its inputs from `ReplState`
  `:96`–`:98`). Missing any of them would make the REPL or a headless agent
  diverge from `run`.
- **Absent vs malformed**: the explicit mechanisms error on a missing file; the
  name convention falls through silently; one loader enforces `---` frontmatter
  and a non-empty `role`.
- **A detached child inherits the launcher's working directory**
  (`src/commands.rs:55`–`:96`) — which is why the new step's *rank* is a
  behavioural question, not a cosmetic one.

## 4. Decisions

- **D-1 — a discovered convention, not an explicit path.** Absent falls
  through; present-but-unloadable is an error.
- **D-2 — ranked directly above the built-in default.** Strictly additive:
  every input that resolved to a persona before resolves to the same one now,
  and only the built-in-default case changes. It also stops a directory from
  silently replacing the role of a spawned `--name reviewer` child, which
  inherits that directory. The instruction does not state a rank (最優先事項
  marks the cycle's priority, as in previous cycles), so this is recorded as an
  open decision in all three documents, with the cost of the alternatives in
  design §9.
- **D-3 — no silent absorption.** The file in use is reported; a bad one
  refuses to start.
- **D-4 — resolve the candidate once, test its existence every time.** A
  session cannot drift to another directory, and a `persona.md` written
  mid-session is picked up by `/reload-persona`.

### Two amendments, both forced by measurement

1. **The discovery helper is the candidate form only.** The design first listed
   an exists-gated `local_persona_path` / `local_persona_path_in` pair beside
   it. Every consumer wants the *candidate* (D-4 — existence is re-tested
   inside `resolve`), so the pair would have had no caller, and an uncalled
   `pub fn` in a binary crate is a dead-code warning, which NFR-03 forbids.
   The existence test lives where the decision is made.
2. **The malformed-file error is prefixed with the file.** Running the
   malformed cases end to end showed `Persona::load` names the file only when
   it cannot *read* it — the frontmatter faults carry the fault alone. For
   `--persona` / `persona_file` that is enough, because the user just named the
   file; for a discovered file it is not, and FR-03 demands the name. The
   branch now maps `AppError::Persona(msg)` to
   `project persona <file>: <msg>`, matching on the variant so `Display`'s
   `persona error:` prefix is not doubled. Recorded as BL-11.
